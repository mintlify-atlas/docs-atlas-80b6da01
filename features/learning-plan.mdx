title: "Learning plan"
description: "AI-generated personalized 4-week study plans tailored to your soft skills profile and Moodle progress."
---

A learning plan is a 20-day (4-week, 5 days per week) structured study program generated by Kairo's AI. Every plan is unique to you — it targets your weakest soft skill, adapts to your learning style, and focuses on topics relevant to your current module.

## Plan types

Kairo generates two types of plans depending on the data available for you:

<CardGroup cols={2}>
  <Card title="Interpretive" icon="brain">
    Soft-skills focused. Generated when Moodle progress data is not yet available or not significant. Prioritizes the five soft skill dimensions from your `soft_skills_assessment` and the module's topic list.
  </Card>
  <Card title="Analytical" icon="chart-line">
    Moodle-data driven. Generated when `moodle_progress` data is present. Incorporates your `average_score`, `current_week`, and `struggling_topics` to produce exercises that directly address your academic weak points.
  </Card>
</CardGroup>

The `plan_type` is stored in `complementary_plans.moodle_status_snapshot->>'plan_type'` and displayed as a chip on the AI Trainer header.

```sql
-- Requesting a plan
POST /api/coder/plan/request

-- Body
{ "plan_type": "interpretive" }  -- or "analytical"
```

<Note>
Only one plan can be active at a time. Requesting a new plan automatically deactivates the previous one (`is_active` is set to `FALSE`).
</Note>

## The 6 cards structure

Each plan contains exactly **6 cards** stored as rows in `complementary_plans`, each assigned a priority level:

```sql
CREATE TYPE priority_level_enum AS ENUM ('low', 'medium', 'high');

-- Column on complementary_plans
priority_level priority_level_enum DEFAULT 'medium'
```

| Priority | Cards | Focus |
|---|---|---|
| `high` | 2 | Directly target your `struggling_topics` or weakest soft skill |
| `medium` | 2 | Reinforce related concepts from the current module |
| `low` | 2 | Broader enrichment topics to round out your knowledge |

Cards are sorted by priority when displayed on the dashboard, so the most important material always appears first.

## Daily activities

Each card contains **20 days of activities** spread across 4 weeks. Activities are stored in `plan_activities`:

```sql
CREATE TABLE plan_activities (
  id                    SERIAL PRIMARY KEY,
  plan_id               INT NOT NULL,
  day_number            INT NOT NULL,
  title                 VARCHAR(200) NOT NULL,
  description           TEXT,
  estimated_time_minutes INT,
  activity_type         activity_type_enum,
  skill_focus           VARCHAR(100),
  FOREIGN KEY (plan_id) REFERENCES complementary_plans(id) ON DELETE CASCADE
);
```

Each day contains two activities:

- **Technical activity** — a coding or conceptual task for the current module topic.
- **Soft skill activity** — a reflection or collaboration exercise targeting your `skill_focus`.

## Activity types

The `activity_type_enum` controls how much guidance an activity provides:

```sql
CREATE TYPE activity_type_enum AS ENUM (
  'guided',
  'semi_guided',
  'autonomous'
);
```

| Type | Description |
|---|---|
| `guided` | Step-by-step instructions with worked examples. Suitable for new concepts. |
| `semi_guided` | A starting point and hints, but you complete the steps. Builds confidence. |
| `autonomous` | Open-ended challenge with no hand-holding. Tests independent problem-solving. |

The balance of activity types shifts toward `autonomous` as your `autonomy` score improves across plans.

## Completing a day

To mark a day as done, click **Completado** on both the technical and soft skill activity cards, then confirm. This calls:

```http
POST /api/coder/plan/:planId/day/:day/complete
```

Kairo records the completion in `complementary_plans.completed_days` (a JSONB map of `{ "1": { "completedAt": "..." }, ... }`) and writes rows to `activity_progress` for each `plan_activities` row associated with that day:

```sql
INSERT INTO activity_progress
  (activity_id, coder_id, completed, completed_at)
VALUES ($1, $2, true, NOW())
ON CONFLICT (activity_id, coder_id)
DO UPDATE SET completed = true, completed_at = NOW();
```

Completing a day awards **Kairo Score** points. Completing all 20 days awards a bonus.

## Marking individual activities done

You can also mark a single activity complete without finishing the whole day:

```http
PATCH /api/coder/activities/:id/complete
```

The request body can include:

```json
{
  "reflectionText": "What I learned today...",
  "timeSpent": 45
}
```

These are stored in `activity_progress.reflection_text` and `activity_progress.time_spent_minutes`.

## Evidence submissions

For activities that require you to produce something tangible, you can submit evidence. See [Assignments & evidence](/features/assignments) for the full workflow.

<Tip>
If you complete all 20 days, your next plan is generated automatically the following Monday — you don't need to request it manually.
</Tip>
